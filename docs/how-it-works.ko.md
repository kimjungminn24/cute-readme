## 도트 테마의 글자

`pixel`은 글자를 `<text>`가 아니라 **도트로 찍습니다.** 한글 설명까지 어디서나 도트로 보입니다.

`<img>`로 불러온 SVG는 **보는 사람 컴퓨터에 깔린 글꼴만** 씁니다. 한글 픽셀 글꼴은 대부분 안 깔려 있어서, 글꼴 이름만 지정하면 리포 이름은 도트인데 한글 설명만 일반 명조로 떨어집니다. 그래서 링크 뱃지가 영문에 쓰는 방법(글자를 도형으로 그리기)을 한글까지 넓혔습니다.

글자 비트맵은 [assets/galmuri11.dot](../assets/galmuri11.dot)에 있습니다. [Galmuri11](https://github.com/quiple/galmuri)(SIL OFL 1.1)의 BDF에서 한글 음절과 ASCII, 낱자만 추려 구운 340KB 블롭입니다. 워크플로와 에디터가 이걸 읽어 `renderRepoCard(repo, { dots })`로 넘깁니다. **못 읽어도 카드는 나옵니다.** 조용히 `<text>`로 돌아갑니다.

글꼴에 없는 글자(한자, 이모지)가 섞인 줄은 그 줄만 `<text>`로 그립니다. 섞어 쓰면 같은 줄에서 글자 높이가 달라져 더 어색하기 때문입니다.

> 글자가 도형이라 SVG 본문에는 글씨가 안 남습니다. 대신 `<title>`과 `aria-label`에 `owner/repo`가 들어가 있어 화면 낭독기와 검색에는 잡힙니다.

블롭을 다시 구우려면 [배포 페이지](https://github.com/quiple/galmuri/tree/main/dist)에서 `Galmuri11.bdf`를 받아:

```bash
node scripts/build-dotfont.js Galmuri11.bdf assets/galmuri11.dot
```

없는 리포나 `owner/repo` 형식이 아닌 항목은 건너뛰고 나머지 카드는 그대로 갱신됩니다. `cards.json`이 아예 없으면 워크플로는 아무것도 안 하고 지나갑니다.

이전된 리포는 **현재 주소**로 그려집니다 (`facebook/react`를 적으면 카드와 링크가 `react/react`로 나옵니다). GitHub API가 리다이렉트로 알려주기 때문입니다.

로컬에서 미리 보려면:

```bash
npm run render:cards -- cards.json cards
```
## 누가 큰 알이 되는가

순위는 GitHub이 매겨서 줍니다. `GET /repos/{owner}/{repo}/contributors`가 **커밋 수 내림차순으로 정렬된 목록**을 주고, 각 항목에 `login`, `avatar_url`, `contributions`(커밋 수)가 들어 있습니다.

크기 단계는 그 커밋 수를 **로그로 눌러서** 정합니다. 그대로 비례시키면 500커밋 옆의 20커밋이 0.04라 1등 빼고 전원 최소 크기가 됩니다. 오래된 리포는 거의 다 이 모양이라 그러면 통이 좁쌀로만 찹니다. 로그를 씌우면 20커밋도 중간쯤에 앉아서, 격차는 남기면서 그림이 나옵니다.

여기에 **순위가 상한으로 걸립니다.** 2등은 아무리 커밋이 많아도 2단계 아래까지고, 3등은 3단계 아래까지입니다. 1등과 2등의 커밋 수가 비슷한 리포가 흔한데(`facebook/react`가 그렇습니다) 가장 큰 알이 둘이면 원작의 사다리가 무너지고 통도 그만큼 길어집니다. 커밋이 적으면 상한보다 훨씬 아래로 내려갑니다. 2등이라도 1등의 1/400이면 한참 작은 알입니다.

봇 계정(`dependabot[bot]` 등)은 뺍니다. 커밋 수가 사람을 압도해서 통을 혼자 채웁니다.

프로필 사진은 **base64로 SVG 안에 구워 넣습니다.** README에 `<img>`로 들어간 SVG는 바깥 리소스를 못 불러와서, 주소만 적어 두면 알이 전부 빈 원으로 나옵니다. 사진을 못 받은 사람은 아이디 첫 글자로 대신 채웁니다.

미리보기와 `npm run preview:suika`의 예시에는 **사람이 안 나오는 도형 아바타**를 씁니다(`sampleAvatar`). 사진 없는 GitHub 계정에 붙는 무늬와 같은 모양이고, 색은 이웃끼리 최대한 벌어지게 황금각으로 돌려서 뽑습니다. 예시에 남의 얼굴을 박아 둘 이유가 없어서입니다. 진짜 사진이 어떻게 잘리는지는 `npm run preview:suika -- owner/repo`로 확인하세요.

## 쌓인 모양

**그릴 때 물리를 한 번 돌려서 정합니다.** README에 `<img>`로 들어간 SVG는 스크립트가 죽으므로 브라우저에서 굴릴 수가 없습니다. 대신 Node에서 큰 알부터 하나씩 떨어뜨려 나온 좌표를 SVG에 구워 넣고, **떨어지는 연출만 CSS 애니메이션으로** 흉내냅니다.

곧게 떨어뜨리기만 하면 알이 남의 어깨에 아슬아슬하게 걸린 채로 굳어서, 쌓인 게 아니라 공중에 붙여 놓은 그림이 됩니다. 그래서 한 알 위에 얹힌 알은 **경사면을 따라 굴려서** 두 군데가 닿거나 바닥에 앉을 때까지 내려보냅니다.

배치 씨앗은 **기여자 목록에서만** 뽑습니다. 난수를 쓰면 매일 도는 워크플로가 커밋 수도 안 바뀐 SVG를 좌표만 흔들어서 다시 커밋합니다. 테마는 씨앗에 안 섞습니다. 섞으면 테마를 고르는 게 아니라 배치를 다시 뽑는 꼴이 됩니다.

## 턴테이블은 왜 안 도나

방의 턴테이블은 아이소메트릭이라 판이 비스듬한 타원입니다. 도트로 찍은 타원을 회전시키면 계단까지 같이 돌아 지저분해집니다. 그래서 판은 세워두고 라벨만 `scaleX`로 4컷 뒤집습니다. 지구본이 대륙만 돌리는 것과 같은 방법입니다.
